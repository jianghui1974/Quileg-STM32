# 示例流程

两个最小示例，用来验证"设备 → 串口 → 上位机"整条链路通不通。

| 文件 | 做什么 | 风险 |
|---|---|---|
| `01-mouse-square.quileg` | 鼠标画一个方框 + 蜂鸣器提示 | 无输入，最安全 |
| `02-type-hello.quileg` | 在**当前焦点窗口**输入 `hello` 并回车 | 会真的打字，先切到一个空白文本里 |

## 格式

纯文本，一行一条指令：

```
FF 02 00 40 00 00 00 00 00 00 00 FE // 鼠标右移 64
└─ 帧头                      帧尾 └─ 注释
```

- `FF` … `FE` 之间是 10 字节有效数据，见 [`../docs/protocol.md`](../docs/protocol.md)。
- `//` 后面是注释，不影响执行。
- 空行和 `*` 开头的说明行会被忽略。

## 关于最后一字节（`[9]`）

示例里有些行用 `[9] = 0x0A`（10）表示"重复 10 次"。**固件不读这一位**——是网页助手在发送时展开成 10 帧。所以：

- 用网页助手打开：按重复次数执行。
- 自己写脚本直接发串口：**需要自己循环发 10 次**。

## 用法

1. 打开 `../tools/web-assistant/quileg-assistant.html`，连接串口。
2. 导入本目录的 `.quileg` → 执行。
3. 听到蜂鸣器、看到鼠标动，就说明链路通了。

> 两个示例都**不含**任何网络请求、账号或平台相关操作，可以放心先跑。

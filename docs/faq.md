# 常见问题

## 还能买到成品吗？

不能。前两代**从未公开发布**，也没有量产销售。本仓库是当年源码的归档。

## 能自己做一台吗？

可以，但要自己解决硬件：

- 核心件：**Nano STM32 V1.1**（慧勤智远）或同规格的 STM32F103C8T6 板——8 MHz + 32.768 kHz 晶振、原生 USB（键鼠 HID）、CH340X 串口；再加 7 个按键与蜂鸣器；第一代还要一块 128×64 OLED（I²C，接 `PB13/PB15`）。
- 烧录：ST-Link + SWD。
- 引脚与接线见 [hardware.md](hardware.md)。

**没有提供**原理图、PCB、BOM、外壳文件——需要你按引脚表自己画。

## 支持 Windows / Linux 吗？

设备是**标准 USB HID 键鼠**，理论上三大系统都认。当年主要在 macOS 上使用（流程里含 `⌘` 快捷键、截屏等 macOS 习惯），Windows / Linux 未做系统验证。串口那一侧与操作系统无关。

## 中文能输入吗？

**不能直接打中文**。设备只会发 HID 键码，等于在键盘上敲 ASCII。当年的做法是：

1. 用系统输入法（拼音）敲字母，再选词；
2. 或者先把中文放进剪贴板，再用 `⌘/Ctrl + V` 粘贴。

第二种更稳，也是当年流程里处理长文本的方式。

## 为什么是 9600 波特率？

当年 CubeMX 默认值，够用（一帧 12 字节约 12.5 ms），就没改。**可以改快**，但必须同时改两端：`Core/Serial/Serial.c` 里的 `huart_x.Init.BaudRate` 与上位机的串口设置。注意 F103 的 USB 与高波特率串口同时跑时，别把中断优先级配乱。

## 能无线吗？

不能。F103C8 没有无线模块，只能插 USB 线。要无线就得换方案——第三代换 ESP32-S3 走蓝牙，正是这个原因。

## 设备知道屏幕上发生了什么吗？

**不知道。** 它只负责"按"，不负责"看"。屏幕状态靠人（或上位机的截图 + 外部 OCR）判断。这是前两代最大的架构限制。

## 为什么第二代把屏幕去掉了？

产品上的取舍：屏幕、按键、外壳都会增加成本与装配工序，而实际使用时人并不盯着设备上的小屏。去掉后保留 LED + 蜂鸣器做状态提示。

代价是：**OLED 代码没清理干净**，第二代固件仍在为一块不存在的屏做 I²C 写操作（见 [architecture.md](architecture.md)）。

## 第一代的 OLED 是什么型号？

**0.96 英寸 128×64，型号 `ZJY096I0400WG01`，中景园**。

驱动 IC 是 SSD1306 系列——`oled.c` 的初始化序列是标准 SSD1306 写法（`0xA8,0x3F` 多路复用 64、`0xDA,0x12` COM 配置、`0x8D,0x14` 开电荷泵、`0xB0|page` 页寻址）。

接线是软件 I²C：`PB13 = SCL`、`PB15 = SDA`（早期面包板原型用的是 `PB8/PB9`，别照旧图接）。

## 救砖：ST-Link 连不上了怎么办？

BOOT0 置 1 → 复位进系统 Bootloader → STM32CubeProgrammer 连上后 **Full chip erase** → BOOT0 回 0 → 复位 → 重新烧写。完整步骤见 [development-notes.md](development-notes.md) 第三节。

## 官网说的"多机并联"是怎么实现的？

靠**设备外壳内置的 USB HUB**，不是固件功能：一个外壳里放多块主控板，每块各自作为独立的 HID 键盘/鼠标枚举，USB 全部接到内置 HUB，再由一根线出到电脑——所以电脑上看到的是**多组键鼠设备**。外壳上还有一个**三档旋钮，用来切换 HUB 的连接方式**（关机 / 被控 / 自控）——切换的**硬件在已生产的机器上是做出来的**，但配套的**应用软件没有开发**。

**固件这边没有主从、同步或总线协议**（`Serial.c` / `main.c` 逐行确认过），每块板子只认自己串口收到的帧。分工是：**HUB 负责聚合（硬件），网页助手负责分配（每块板子一个串口、一个浏览器页面）**。

具体操作：每块板子各有一个串口 → 打开多个浏览器页面 → 每页的网页助手在「连接」时选**不同的串口** → 各跑各的流程。

注意多块板子同时注入键鼠时事件会交错，只在"各操作不同窗口或不同机器"时才有意义；一条 USB 线上接太多组 HID 也可能不稳定（未实测上限）。

## 插到 Mac 上它自己动、还截屏了？

那是**第二代固件的上电自检**（2025 年调试留下的）：蜂鸣器响两声 → 鼠标画方框 → 按 `⌘+Shift+3` 与安卓截屏组合键 → 响三声。

- 想保留自检：知道就行，别在重要窗口前上电。
- 想关掉：自行注释 `Core/Src/main.c` 里的演示调用后重新编译（归档版不提供补丁）。

## 能用它做"自动发内容 / 批量采集"吗？

技术上，屏幕上能手动做的它都能复现。但**请你只在你有权操作的设备与账号上使用**，并遵守目标平台的服务条款与法律。批量采集他人内容、规避平台技术措施、刷量或欺诈，都超出本项目的用途与许可意图。详见 [legal-and-safety.md](legal-and-safety.md)。

## 会被平台判定为作弊 / 封号吗？

从设备角度，它发出的是**真实的 USB 键鼠事件**，与人工输入在系统层面没有区别。但平台仍可能依据**行为特征**（频率、规律性、路径）做风控。请自行评估，不要用于违反平台规则的操作。

## 为什么不再维护了？

因为它要解决的问题（稳定地"替人点电脑"）已经被更好的形态取代：直接用浏览器/接口拿数据，或者让 AI 通过投屏 + 闭环操作设备。继续在这块 F103 上加功能，性价比不高。

## 会提供技术支持、修 bug 或出补丁吗？

**不会。** 这是**归档发布**：不接受功能请求、不修 bug、不回答使用问题，也**不提供任何补丁**（包括关闭上电自检那种小改动）。源码就是 2024–2025 年的最终样子，请当作一份只读的历史资料。

## 上位机页面打不开 / 连不上串口

- 必须用**桌面版 Chrome 或 Edge**（Web Serial API 目前只有 Chromium 系支持）。
- 页面首次打开需要联网（jQuery 等从 CDN 加载）。
- 「连接」按钮无反应：检查浏览器是否弹出了串口选择框、设备是否被别的程序占用、USB-TTL 驱动是否装好。
